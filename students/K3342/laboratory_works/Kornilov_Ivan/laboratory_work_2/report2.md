## Практики 2.1–2.3. Автовладельцы

**Каталог:** `django_project_kornilov`  
**Приложение:** `project_first_app`

Проект называется `django_project_kornilov`, приложение — `project_first_app`, как в практическом задании.

Владелец автомобиля — пользователь. Модель `CarOwner` наследует `AbstractUser`, поэтому у него есть логин и пароль, а дополнительные поля лежат в той же таблице. В `settings.py` указано `AUTH_USER_MODEL = 'project_first_app.CarOwner'`.


| Модель         | Что хранит                                                           |
| -------------- | -------------------------------------------------------------------- |
| CarOwner       | фамилия, имя, дата рождения, паспорт, адрес, национальность          |
| Car            | гос. номер, марка, модель, цвет                                      |
| Ownership      | владелец, автомобиль, дата начала и дата окончания                   |
| DrivingLicense | владелец, номер удостоверения, тип (A, B, C, D, BE, CE), дата выдачи |


Связь владельца и автомобиля — многие-ко-многим через `Ownership`, потому что у владения есть собственные даты. Тип удостоверения — поле `choices`.

```python
class Car(models.Model):
    license_plate = models.CharField('Гос. номер', max_length=15)
    brand = models.CharField('Марка', max_length=20)
    model_name = models.CharField('Модель', max_length=20)
    color = models.CharField('Цвет', max_length=30, null=True, blank=True)
    owners = models.ManyToManyField(CarOwner, through='Ownership', related_name='cars')
```

Команда `python manage.py seed` создаёт пять владельцев и семь автомобилей. У Ивана Петрова и Марии Соколовой не меньше трёх машин, периоды владения одним автомобилем не пересекаются: следующий владелец начинается после даты окончания предыдущего.

Все четыре модели зарегистрированы в `admin.py`. У владельца в админке видны паспорт, адрес и национальность.

Карточка владельца — функциональное представление. Адрес `/owner/<id>/` передаёт идентификатор в `owner_detail`, шаблон `owner.html` показывает паспорт, адрес, национальность, удостоверения и автомобили.

```python
def owner_detail(request, owner_id):
    owner = get_object_or_404(CarOwner, pk=owner_id)
    return render(request, 'owner.html', {'owner': owner})
```

Список владельцев тоже написан функцией. Список автомобилей, карточка, создание, изменение и удаление — классовые представления `ListView`, `DetailView`, `CreateView`, `UpdateView` и `DeleteView`. Форма нового владельца создаёт пользователя: пароль сохраняется через `set_password`, вместе с ним записываются паспорт, адрес и национальность.

**Запуск:** `python manage.py migrate`, `python manage.py seed`, `python manage.py runserver`.

**Ожидаемый результат:** [http://127.0.0.1:8000/owner/1/](http://127.0.0.1:8000/owner/1/) открывает Ивана Петрова. Вход в админку: `admin` / `admin12345`.

## Вариант 5. Список научных конференций

**Каталог:** `conference_site`  
**Приложение:** `conferences`

Сайт хранит конференции, тематики, заявки авторов на доклады и отзывы. У конференции есть название, список тематик, место и описание места, период проведения, описание и условия участия. Заявка связывает автора и конференцию названием доклада и тезисами. Отзыв хранит даты конференции, текст, оценку от 1 до 10 и автора комментария.


| Модель           | Поля                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------- |
| Topic            | название тематики                                                                       |
| Conference       | название, тематики, место, описание места, начало, окончание, описание, условия участия |
| TalkRegistration | автор, конференция, название доклада, тезисы, рекомендация к публикации                 |
| Review           | конференция, автор, даты конференции, текст, рейтинг 1–10                               |


Пользователь регистрируется, смотрит конференции и подаёт доклад. Свои заявки он меняет и удаляет на странице «Мои доклады». Чужую заявку удалить нельзя: представление ищет запись только среди докладов текущего пользователя.

При публикации отзыва в запись копируются даты выбранной конференции, текст, рейтинг и пользователь, который оставил комментарий. На карточке конференции эти поля видны рядом с отзывом.

Результат выступления — поле «рекомендован к публикации». В Django-admin у регистраций есть действия «Рекомендовать к публикации» и «Не рекомендовать к публикации». В клиентской части то же решение принимает сотрудник оргкомитета: на странице участников кнопки «Рекомендовать» и «Отклонить» рисуются только при `user.is_staff`. Обычный автор видит таблицу и колонку результата, но не эти кнопки. Запрос от участника без прав сотрудника отвечает 403.

```python
{% if user.is_staff %}
  <button type="submit" name="decision" value="yes">Рекомендовать</button>
{% endif %}
```

Таблица всех участников строится в клиентской части, на странице `/participants/`. Колонки: конференция, участник, доклад и результат. Список можно сузить конференцией и строкой поиска по фамилии, названию доклада или конференции.

Список конференций, свои доклады и участники разбиты на страницы. У конференций дополнительно фильтр по тематике. Номер страницы передаётся отдельно от строки поиска, поэтому фильтр не сбрасывается при переходе дальше.

Интерфейс собран своими стилями: тёмная шапка, карточки конференций, таблицы и формы.

**Запуск:** в каталоге `conference_site` выполнить `python manage.py migrate`, `python manage.py seed`, `python manage.py runserver`.

**Ожидаемый результат:** на главной четыре конференции, на второй странице остаются ещё две. Участник `anna` / `guest12345` видит свои доклады и может их изменить. Сотрудник `admin` / `admin12345` на `/participants/` рекомендует доклад к публикации. В таблице есть Анна Ковалёва и Пётр Орлов. В админке тот же результат ставится действием.
